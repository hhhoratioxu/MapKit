# MapKit Loon 优化与验证边界

核对日期：2026-10-20。基线为 `NSRingo/MapKit@c9af737d97c0b3e26bc2f1083e36564da1b05ba4`，协议包为锁定的原始 `@nsringo/mapkit@1.1.3`。

## 处理方式

Loon Request 只处理精确的 HTTPS 清单和公告路径。清单请求根据原生参数选择地区，按上游的合成方向读取另一地区：CN 对应 US，其他地区对应 CN。每次最多一个附加请求，不下载当前合成逻辑未使用的第二份清单。公告只按已选环境调整 query；配置请求的缓存条件 Header 使用原生 Rewrite 删除。

补充数据只从对应 Apple 主机获取。HTTP 使用官方 `timeout` 毫秒、`binary-mode=true`、`auto-cookie=false`、`auto-redirect=false`、`insecure=false`。完成前等待网络回调，重复回调只处理第一次；超出本次预算的回复不写缓存。脚本超时 8 秒，HTTP 设置限制在 500–6000 毫秒。没有依赖计时器取消、请求取消或未公开的宿主参数。

Request 保持轻量，只检查 protobuf wire 边界；Response 用原始协议包做语义解码，确认可用的瓦片和服务集后才合并。无效补充清单会失效并进入冷却。主响应异常、格式未知、错误状态、缺失补充数据或任意转换失败均返回空修改对象，保留原响应。仅在修改正文后清理旧的长度、编码、ETag 等 Header，并设置 no-store。

普通网络配置使用独立的 XML 脚本，防止每次启动 protobuf 解析器。只在识别到上游的 `com.apple.GEO.CountryProviders.CN` 结构时启用上游同组功能；未知结构保持原样。

## 容量和一致性

| 项目 | 边界 |
| --- | --- |
| 缓存新鲜期 | 默认 3600 秒；允许 0–86400 秒；0 表示每次重新验证 |
| 旧补充清单可用期 | 默认 24 小时；允许 0–72 小时；新鲜期内清单仍可使用 |
| 失败冷却 | 默认 30 秒；合法数字 Retry-After 限制为 30–300 秒 |
| 持久缓存 | `Horatio.MapKit.v1.` 下 4 个固定槽位及一个最多 16 KiB 的索引 |
| 单槽正文 | 原始数据最多 1 MiB；Base64 后约 1.34 MiB，另有少量键值元数据 |
| 主清单解码 | 原始数据最多 2 MiB；合成输出最多 4 MiB |
| 分组扩张 | 调用 tileGroups 前，组数乘以引用集合数量最多 200000 |
| XML 配置 | 使用保守 UTF-8 上界，正文与结果各最多 256 KiB |

缓存键保留完整查询参数，按参数名规范化，区分 Apple 主机、国家、系统、硬件和版本；拒绝重复参数和过长键，避免不同请求被意外合并。只读取实际选中的正文槽位。写入某地区时不重置其他地区或其他插件的持久存储。

Loon 同步存储没有事务或原子交换保证。固定槽位中的正文与索引用完整键和 generation 双重匹配；并发冲突按缓存缺失处理，可能失去一次命中，不能保证同时到达的多个脚本只有一次网络请求。没有跨脚本的伪锁或轮询等待。存储不可用时可能失去缓存优化，但仍保留 Apple 原始响应。

脚本长度检查发生在宿主读取响应之后，不是宿主内存配额，也不能限制完整解码对象的所有分配。这里没有对 Loon 内存上限作假设。

## 自动验证

`npm test` 覆盖上游测试与新增回归：两地区缓存共存、槽位上限、异常存储、完整 query 隔离、Base64/线格式边界、ETag/304、429/冷却、超时与晚回调、重复回调、凭据 Header 不转发、失败保留主响应、默认组合、未知数字枚举、未知 protobuf 字段、引用扩张边界，以及 400 组生成布局与真实上游算法的结果一致性。

`npm run build:loon` 对实际编译后的三个运行脚本执行 12 个模拟 Loon 场景，检查单次 `$done`、正常合成、原生对象参数、新鲜缓存不联网、公告、错误状态、无数据和异常正文。生成插件也会检查参数声明、URL Guard、固定运行地址和不应出现的其他客户端字段。没有调用真实 Loon 配置解析器。

`node scripts/measure-work.mjs` 直接从上述 Git 提交读取上游算法，比较分组瓦片结果和已知字段 protobuf 输出，并记录每组九次 Node/V8 测量的全部样本。100 次同查询、处于新鲜期内的模拟执行中，上游 Request 发起 100 次附加 HTTP，本版发起 1 次。这是特定重复场景的工作量结果，不能推广为整机网络、耗电或内存降低比例。

实际结果和运行环境保存在 `build-validation.json` 与 `work-measurements.json`。桌面和 CI 的时间样本会随平台、Node 版本及系统负载改变；产物字节校验与真实设备体验分开记录。

## 仍待实机确认

尚未验证真实 iPhone 的 Loon 导入、地图/卫星/四处看看呈现、系统缓存刷新、真实网络延迟、耗电和长期 VPN 稳定性。Apple 的地区覆盖、服务器变化与当前路由会影响实际效果。不可由本次自动测试宣称这些验收已完成。
