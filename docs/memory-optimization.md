# MapKit 4.6.1-optimized.2 内存优化

日期：2026-11-01。比较基线为上一发布版 `a0451d9cfc7e289d7040e6076239b9b6c5ba74bd`（`optimized-v1-lpx`）。当前运行脚本固定在 `optimized-v2`，安装入口继续为 `MapKit.lpx`。

## 实际改动

1. **缓存按需解码。** 原来 Request 为判断缓存新鲜度和 ETag 可用性，会 JSON.parse 整条记录、复制 Base64 字符串，再创建完整 Uint8Array。现在只解析有长度边界的元数据，直接在原存储字符串的 Base64 区间校验编码和 protobuf framing。Response 需要真实合成时才解码一次。仍读取实际槽位并匹配完整键和 generation，不能只凭索引认定命中。重排字段、空白或转义的旧记录走兼容解析，不迁移或清空缓存。
2. **减少编码临时对象。** 原 Base64 编码每三个字节生成和串接小字符串；新版最多复用 8192 字节暂存区，再合并有界小块。写入仍是原来的 JSON 格式，元数据用 JSON.stringify 转义，已验证的 Base64 直接拼接，避免再次序列化大字段。
3. **复用地图分组引用。** 同一响应的每个 tileGroup 原先独立构造相同的瓦片索引对象和资源索引数组。Loon 路径在编码期间共享这些只读表，不共享跨请求的可变解码对象。2000 瓦片、60 分组的样本中，瓦片引用对象由 120000 个降为 2000 个；最终 protobuf 仍写入各组所需的完整内容。其他共享类调用方默认保留独立数组行为。
4. **及时结束与释放引用。** 无网络的 Request 路径和完整 Response 同步调用一次 `$done`，不再额外排队 Promise。网络路径继续等回调完成。合成阶段完成选择后解除对未使用源集合的引用，使垃圾回收可以在编码输出期间回收它们；不强制调用宿主 GC。

缓存容量、TTL、失败回退、查询次数、超时、正文与输出边界、地图设置都保持原值。原始协议包仍为 `@nsringo/mapkit@1.1.3`，不替换 schema，不删除未知字段支持。

## 实际 bundle 对比

`node scripts/measure-memory.mjs` 从固定 Git 提交读取上一版 bundle，和当前三个运行资源中的 request/response 比较。使用自写数据、固定时间和随机数；每个版本/场景运行五个全新进程，交替顺序，共 **90 个独立 Node/V8 进程**。所有输出和写入的持久记录经 SHA-256 对比一致。完整环境、每次样本、bundle 摘要和输入摘要在 [memory-measurements.json](memory-measurements.json)。

以下为本地 macOS arm64、Node v24.22.1 的中位数；RSS 是整个桌面进程的历史峰值，包括 Node、VM 与 fixture 初始化开销，不能当作 Loon 的脚本或 VPN 峰值。

| 合成场景 | 旧版峰值 RSS | 新版峰值 RSS | 旧版耗时 | 新版耗时 |
| --- | ---: | ---: | ---: | ---: |
| 1 MiB 新鲜缓存检查 | 64.5 MiB | 58.9 MiB | 16.43 ms | 2.95 ms |
| 2000 瓦片的新鲜缓存检查 | 60.5 MiB | 56.9 MiB | 4.52 ms | 2.49 ms |
| 1 MiB 缓存 ETag/304 | 64.6 MiB | 58.9 MiB | 16.54 ms | 3.11 ms |
| 1 MiB 缓存写入 | 103.0 MiB | 69.0 MiB | 37.44 ms | 14.72 ms |
| 80 瓦片缓存写入 | 55.2 MiB | 55.5 MiB | 1.95 ms | 2.22 ms |
| 80 瓦片/3 分组合成 | 59.0 MiB | 59.0 MiB | 10.26 ms | 10.38 ms |
| 2000 瓦片/60 分组合成 | 106.7 MiB | 100.9 MiB | 326.46 ms | 320.25 ms |
| 缺少补充清单 | 57.0 MiB | 57.0 MiB | 5.91 ms | 5.78 ms |
| 超限正文放行 | 66.1 MiB | 66.0 MiB | 5.04 ms | 5.11 ms |

缓存写入的主要大数据场景峰值 RSS 下降约 **33%**。新鲜缓存和 304 的显式 Uint8Array 分配从 1 MiB 变为 0；存储本身返回的大字符串仍然存在，不能据此声称完全不占内存。大型合成的峰值 RSS 下降约 **5.4%**，编码器仍需完整序列化输出。

小清单写入的 RSS 增加约 0.3 MiB、耗时增加约 0.27 ms；小合成和放行路径基本持平，有轻微上下波动。未将这些场景报告为收益。初次实现的逐字符 Base64 校验出现明显耗时退化，已改为在原字符串区间上执行有界 sticky 正则校验；这里只记录最终发布实现的数据。

`sampledHeapGrowthBytes` 仅在持久写入与完成时采样，可能包括尚未回收的垃圾，不是连续观测的堆峰值；`explicitArrayBytes` 只统计可拦截的 Uint8Array 构造，不包括原生 TextEncoder、内部视图和宿主缓冲。进程峰值 RSS、这些辅助指标和源码确定的对象数量应分别解读。

## 验证范围

- 117 项回归通过，包括原有测试、2000 组随机 Base64/线格式差分、合法多线型与字段数上限、400 组瓦片布局比较、损坏/并发替换/过期缓存、旧 JSON 兼容、存储异常、ETag/304、回调和失败放行。
- 14 个实际编译 bundle 场景通过，检查原生参数、URL Guard、`.lpx` 固定版本引用、同步本地完成、真实异步等待和一次 `$done`。
- 90 个桌面独立进程的输出与持久缓存摘要一致；代码与源协议包保持可重建。[本版 CI](https://github.com/hhhoratioxu/MapKit/actions/runs/41318678974) 在 Linux/Node v22.23.4 上再次通过 117 项测试、14 个编译场景与 90 个独立进程对比。下载并校验 CI ZIP，六个运行资源与本地完全相同；见 [CI 证据](ci-validation-v2.json) 和 [完整云端样本](memory-measurements-ci.json)。旧版 [ci-validation.json](ci-validation.json) 仅属于 optimized.1。
- 未运行真实 Loon 配置解析器，未验证用户 iPhone 地图效果、耗电、原生内存或长时间 VPN 稳定性。JS 边界检查发生在宿主已经取得正文之后，无法给出宿主内存配额或不掉 VPN 的保证。
